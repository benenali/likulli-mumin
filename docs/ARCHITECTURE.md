# التصور المعماري

## المبدأ
واجهة ويب عربية تعمل محلياً أولاً، مع فصل واجهة العرض عن المحتوى الديني والخدمات التي تحتاج اتصالاً. لا تُحمّل الواجهة بيانات غير موثقة على أنها محتوى نهائي.

## التقنية المقترحة
- Next.js + TypeScript لواجهة الويب والتوجيه.
- CSS/Tailwind أو CSS modules بعد اعتماد نظام التصميم؛ دعم RTL من البداية.
- PWA وService Worker لتخزين الملفات الثابتة وصفحات التطبيق، مع استراتيجية تخزين منفصلة للمحتوى.
- IndexedDB للبيانات المحلية الأكبر حجماً؛ localStorage للإعدادات الصغيرة فقط.
- GitHub Actions لفحوص البناء والنوع والاختبارات.
- طبقة بيانات مستقلة تسمح باستبدال مزود المحتوى دون تغيير الواجهة.

## قواعد البيانات والمصادر
- كل سجل ديني يجب أن يحمل معرف المصدر، المرجع، الإصدار/تاريخ المراجعة، وبيانات الترخيص عند الحاجة.
- لا تُخزّن أسرار API في متغيرات NEXT_PUBLIC أو في ملفات الواجهة.
- أي مزامنة مستقبلية تحتاج مصادقة وقواعد وصول واختبارات صلاحيات قبل الإطلاق.
- Supabase ليس شرطاً للنسخة الأولى؛ نؤجل الحسابات حتى تتضح الحاجة وحدود الخطة المجانية.

## العمل دون اتصال
- ملفات الواجهة: cache-first للأصول ذات الإصدارات الثابتة.
- المحتوى: تخزين محلي بإصدارات واضحة مع آلية تحديث وحذف محسوبة.
- طلبات الشبكة الحية: network-first مع رسالة واضحة عند الفشل.
- لا نعد بأن الأذان/التنبيهات تعمل في كل متصفح بالخلفية؛ ذلك يخضع لقيود نظام التشغيل والمتصفح.
- اختبار التحديثات لمنع بقاء نسخة قديمة من البيانات أو ملفات التطبيق.

## الأمان والخصوصية
- عدم تضمين مفاتيح أو بيانات شخصية في المستودع.
- التحقق من المدخلات، تقليل جمع البيانات، وعدم إضافة تحليلات افتراضياً.
- إن أضيفت لوحة إدارة: صلاحيات على الخادم، وليس إخفاء الأزرار في الواجهة فقط.
- توثيق مصادر البيانات وتراخيصها قبل تنزيلها أو إعادة توزيعها.
