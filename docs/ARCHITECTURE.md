# التصور المعماري

## المبدأ
واجهة ويب عربية تعمل محلياً أولاً، مع فصل واجهة العرض عن المحتوى الديني والخدمات التي تحتاج اتصالاً. لا تُحمّل الواجهة بيانات غير موثقة على أنها محتوى نهائي.

## التقنية الحالية
- Next.js + TypeScript لواجهة الويب والتوجيه.
- CSS مخصص مع دعم RTL وتصميم متجاوب.
- PWA: manifest وService Worker وصفحة احتياطية عند انقطاع الإنترنت.
- localStorage للإعدادات الصغيرة؛ IndexedDB سيُستخدم للمحتوى المحلي الأكبر عند بدء ميزات القراءة والحفظ.
- GitHub Actions لفحوص TypeScript وESLint والبناء الإنتاجي.

## الحالة والحدود
- الإعدادات المحلية تعمل عبر localStorage، مع مظهر فاتح/داكن وحجم نص.
- Service Worker يوفّر تخزيناً أولياً للأصول والصفحات التي تمت زيارتها وصفحة Offline احتياطية.
- هذا لا يعني أن كل المحتوى يعمل دون إنترنت؛ المحتوى الديني لم يُضف بعد، ولم يُجر اختبار متصفح فعلي بعد فصل الشبكة.
- يجب اختبار استراتيجية التخزين بعد أول زيارة، وبعد تحديث التطبيق، ومع فشل التخزين أو عدم توفره.

## قواعد البيانات والمصادر
- كل سجل ديني يجب أن يحمل معرف المصدر، المرجع، الإصدار/تاريخ المراجعة، وبيانات الترخيص عند الحاجة.
- لا تُخزّن أسرار API في متغيرات NEXT_PUBLIC أو في كود الواجهة.
- أي مزامنة مستقبلية تحتاج مصادقة وقواعد وصول واختبارات صلاحيات قبل الإطلاق.
- Supabase ليس شرطاً للنسخة الأولى؛ نؤجل الحسابات حتى تتضح الحاجة وحدود الخطة المجانية.

## العمل دون اتصال
- ملفات الواجهة ذات الإصدارات الثابتة: cache-first.
- التنقل بين الصفحات: network-first مع الرجوع إلى صفحة محفوظة أو صفحة Offline عند فشل الشبكة.
- المحتوى: تخزين محلي بإصدارات واضحة مع آلية تحديث وحذف محسوبة.
- طلبات الشبكة الحية: رسالة واضحة عند الفشل.
- لا نعد بأن الأذان/التنبيهات تعمل في كل متصفح بالخلفية؛ ذلك يخضع لقيود نظام التشغيل والمتصفح.
- يجب اختبار التحديثات لمنع بقاء نسخة قديمة من البيانات أو ملفات التطبيق.

## الأمان والخصوصية
- عدم تضمين مفاتيح أو بيانات شخصية في المستودع.
- التحقق من المدخلات، تقليل جمع البيانات، وعدم إضافة تحليلات افتراضياً.
- إن أضيفت لوحة إدارة: صلاحيات على الخادم، وليس إخفاء الأزرار في الواجهة فقط.
- توثيق مصادر البيانات وتراخيصها قبل تنزيلها أو إعادة توزيعها.
