# خطة الاختبارات والقبول

## بوابة كل تغيير
1. مراجعة التغيير والملفات المتأثرة قبل التنفيذ.
2. تنسيق وفحص TypeScript/ESLint.
3. اختبارات الوحدة والمكونات المناسبة.
4. بناء إنتاجي.
5. اختبارات يدوية للوظيفة المتأثرة عند الحاجة.
6. توثيق النتائج الفعلية؛ لا يُقال «أخضر» ما لم يظهر نجاح الاختبار.

## فحوص المرحلة التأسيسية
- [ ] المستودع الصحيح والفرع الافتراضي main.
- [ ] README وخطة المشروع والمعمارية وخطة الاختبارات موجودة.
- [ ] لا توجد أسرار أو مفاتيح فعلية في الملفات.
- [ ] إعداد CI لا يحتاج أسراراً كي يعمل.
- [ ] تثبيت الحزم والبناء وفحص الأنواع ينجح محلياً وفي GitHub Actions.

## اختبارات واجهة أساسية
- [ ] الصفحة الرئيسية تعمل دون أخطاء.
- [ ] RTL صحيح على عرض الهاتف والكمبيوتر.
- [ ] التنقل والروابط لا تؤدي إلى صفحات مفقودة.
- [ ] عناصر التحكم قابلة للاستخدام بلوحة المفاتيح، والتباين مقبول.
- [ ] لا توجد أخطاء Console أو طلبات فاشلة غير معالجة.

## اختبارات Offline
- [ ] فتح التطبيق أول مرة مع اتصال.
- [ ] فتحه مجدداً بوضع الطيران/Offline.
- [ ] بيان واضح لما هو مخزّن وما يحتاج الإنترنت.
- [ ] حفظ المفضلة وموضع القراءة محلياً واسترجاعهما بعد إعادة التحميل.
- [ ] تحديث التطبيق لا يترك ملفات أو محتوى غير متوافقين.
- [ ] مسح التخزين والتعامل مع فشل الحصة التخزينية بأمان.

## اختبارات صحة المحتوى الديني
- [ ] مطابقة النصوص مع مصدر معتمد.
- [ ] مراجعة رقم السورة والآية والترتيب وعلامات الوقف عند اعتماد النص.
- [ ] كل حديث/دعاء/زيارة يحمل مرجعاً مناسباً، ولا تُخلط الأقسام المختلفة.
- [ ] فحص حقوق الاستخدام والتوزيع.
- [ ] مواقيت الصلاة تُقارن بمصدر/طريقة معروفة مع إعدادات المدينة والمنطقة الزمنية والتوقيت الصيفي إن انطبق.

## الأمان والإطلاق
- [ ] لا أسرار في Git أو سجلات البناء.
- [ ] فحص الاعتماديات والثغرات المتاحة.
- [ ] سياسة الخصوصية مفهومة قبل تفعيل الحسابات أو التحليلات.
- [ ] تجربة PWA على Chrome desktop وAndroid إن توفر.
- [ ] لا نشر عام قبل اجتياز بوابات القبول ذات الصلة.
